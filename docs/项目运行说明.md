# 小宇宙桌面版项目运行说明

## 1. 项目简介

小宇宙桌面版是一个面向 macOS 的 Chrome Manifest V3 扩展。项目通过 Chrome
扩展提供节目发现、搜索、订阅、播放和音频下载；通过可选的 Native Host 提供
绝对路径保存、macOS Keychain 凭据管理、本地或云端 ASR 转写及 AI 总结。

本项目与小宇宙官方无隶属、授权或合作关系。请仅处理自己有权访问的内容，并
遵守小宇宙及所选 AI 服务商的使用条款。

## 2. 运行架构

项目由三个部分组成：

1. **Chrome 扩展**
   - `app.html`、`app.js`、`app.css`：桌面窗口和交互界面。
   - `background.js`：Service Worker、设置存储、小宇宙 API 和 Native
     Messaging 调度。
2. **Native Host**
   - `native_host.py`：目录选择、绝对路径写入、Keychain、云端 ASR 和 AI
     总结。
   - `install_native_host.sh`：安装 Native Host 并绑定当前扩展 ID。
3. **本地 Qwen ASR**
   - `local_asr_worker.py`：按任务加载 Qwen3-ASR，任务结束后退出。
   - `install_local_asr.sh`：创建独立 Python 3.12 环境并安装
     `mlx-qwen3-asr`。

## 3. 环境要求

### 基础运行

- macOS
- Google Chrome 110 或更高版本
- 系统自带的 `/usr/bin/python3`
- Git

### 可选依赖

- Homebrew
- `ffmpeg`：本地 Qwen、豆包或 Fun-ASR 处理部分音频格式时需要。
- `uv`：安装本地 Qwen3-ASR 运行环境时需要。
- 对应服务的 API Key：使用云端 ASR 或 AI 总结时需要。

安装可选依赖：

```bash
brew install ffmpeg uv
```

本地 Qwen3-ASR 仅支持 Apple Silicon macOS。Intel Mac 可以运行扩展和
Native Host，但 ASR 应选择 Qwen API 或豆包 API。

## 4. 获取源码

```bash
git clone https://github.com/QWE38qwe/xiaoyuzhou-desktop.git
cd xiaoyuzhou-desktop
```

该项目不需要执行 `npm install`，也没有前端编译步骤。Chrome 可以直接加载
仓库根目录中的扩展源码。

## 5. 加载 Chrome 扩展

1. 在 Chrome 地址栏打开 `chrome://extensions`。
2. 开启右上角的“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择项目根目录，即包含 `manifest.json` 的目录。
5. 记录扩展卡片显示的 32 位扩展 ID。
6. 点击扩展图标，确认能够打开独立桌面窗口。

开发版扩展 ID 由当前源码目录决定。移动项目目录或重新加载为新扩展后，ID
可能变化；此时必须重新安装 Native Host。

## 6. 安装 Native Host

Native Host 是绝对路径保存、API Key 管理、ASR 和 AI 总结功能的基础。

在项目根目录执行：

```bash
chmod +x install_native_host.sh
./install_native_host.sh <chrome://extensions 中显示的开发版扩展ID>
```

示例：

```bash
./install_native_host.sh abcdefghijklmnopabcdefghijklmnop
```

安装脚本会创建：

```text
~/Library/Application Support/Xiaoyuzhou Desktop Native Host/
~/Library/Application Support/Google/Chrome/NativeMessagingHosts/
  com.xiaoyuzhou.desktop.json
```

安装完成后：

1. 返回 `chrome://extensions`。
2. 点击扩展卡片上的“重新加载”。
3. 打开扩展的“设置”页。
4. 确认本地文件助手显示为已连接。

如果使用 Chrome Web Store 版本，可直接执行：

```bash
./install_native_host.sh
```

脚本默认绑定商店扩展 ID。开发者模式必须显式传入开发版扩展 ID。

## 7. 登录与基础功能验证

1. 点击扩展图标打开独立窗口。
2. 点击右上角“登录”。
3. 输入手机号并获取小宇宙短信验证码。
4. 登录后检查发现页是否展示节目和单集。
5. 分别验证搜索、订阅、节目详情、播放和复制链接。

登录令牌保存在 Chrome 扩展本地存储中，只用于访问小宇宙服务。

## 8. 配置保存目录

在“设置”页可以分别配置：

- 音频保存目录
- ASR 转写稿保存目录
- AI 总结稿保存目录

留空时使用默认下载位置。填写 macOS 绝对路径时，扩展会通过 Native Host
创建目录并写入文件。

建议首次运行使用：

```text
~/Downloads/小宇宙音频
~/Downloads/小宇宙转写稿
~/Downloads/小宇宙总结稿
```

## 9. 配置 ASR

### 方案 A：本地 Qwen3-ASR

本地模式不会把音频发送到云端，也不会自动回退到云端 API。

安装运行环境：

```bash
chmod +x install_local_asr.sh
./install_local_asr.sh
```

安装完成后，在设置页选择：

```text
ASR 服务：本地 Qwen3-ASR
本地模型：Qwen/Qwen3-ASR-0.6B
```

可选模型：

| 模型 | 说明 |
| --- | --- |
| `Qwen/Qwen3-ASR-0.6B` | 默认模型，内存占用较低 |
| `Qwen/Qwen3-ASR-1.7B` | 精度更高，内存和磁盘占用更大 |

模型会在首次使用时下载到 Hugging Face 缓存。每次转写启动独立 Worker，
完成后进程退出并释放模型内存。

### 方案 B：Qwen API

推荐的长音频配置：

```text
API Base URL：https://dashscope.aliyuncs.com/api/v1
模型：qwen-audio-3.0-asr-flash-filetrans
```

程序会根据模型自动选择 DashScope 异步、同步或 OpenAI-compatible 协议。
Fun-ASR-Flash 单次最多处理约 5 分钟，长播客应使用 `filetrans` 模型。

### 方案 C：豆包 API

在设置页选择“豆包 API”，填写自己的 API Key、Endpoint 和 Resource ID。
部分音频格式会先由 Native Host 使用 `ffmpeg` 转换。

API Key 不写入扩展存储，而是由 Native Host 保存到 macOS Keychain。

## 10. 配置 AI 总结

AI 总结支持 Qwen、豆包、DeepSeek、Kimi 和 GLM 的
OpenAI-compatible Chat Completions 接口。

默认配置：

| Provider | Base URL 或完整 Endpoint | 默认模型 |
| --- | --- | --- |
| Qwen | `https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions` | `qwen-plus` |
| 豆包 | `https://ark.cn-beijing.volces.com/api/v3/chat/completions` | `doubao-seed-2-1-pro-260628` |
| DeepSeek | `https://api.deepseek.com/chat/completions` | `deepseek-v4-flash` |
| Kimi | `https://api.moonshot.cn/v1/chat/completions` | `kimi-k2.6` |
| GLM | `https://open.bigmodel.cn/api/paas/v4/chat/completions` | `glm-5.2` |

接口地址可以填写 Base URL，也可以填写完整的 `chat/completions` 地址。Native
Host 会在对应 Provider 的官方 HTTPS 域名上补全标准路径。

点击“AI 总结”时：

1. 如果该单集已有转写稿，则直接总结。
2. 如果没有转写稿，则先执行当前 ASR，再执行总结。
3. 长转写稿会自动分段处理并合并结果。
4. 结果保存为独立 Markdown 文件。

首次总结前会展示数据外发和可能产生 API 费用的确认提示。

## 11. 开发检查

项目没有构建命令。修改源码后执行以下静态检查：

```bash
node --check app.js
node --check background.js
/usr/bin/python3 -m py_compile native_host.py local_asr_worker.py
/usr/bin/python3 -m json.tool manifest.json >/dev/null
sh -n install_native_host.sh
sh -n install_local_asr.sh
```

检查通过后，在 `chrome://extensions` 中点击“重新加载”，再进行真实页面验证。

## 12. 验收清单

### 基础功能

- 扩展图标能打开或聚焦独立窗口。
- 登录后发现页、搜索页和我的订阅能加载内容。
- 三个页面都能进入节目详情。
- 单集可以播放、调整进度和倍速。
- 节目链接和单集链接可以分别复制。
- 音频可以保存到浏览器下载目录或配置的绝对路径。

### ASR 与总结

- 设置页能在本地 Qwen、Qwen API 和豆包 API 之间切换。
- 转写结果为 Markdown 文件。
- 本地 ASR 完成后没有残留 Worker 进程。
- AI 总结可以自动执行缺失的 ASR 前序步骤。
- AI 总结稿写入独立目录。
- API Key 不出现在扩展存储、项目文件或日志中。

## 13. 常见问题

### 本地文件助手未连接

确认安装脚本使用的是当前开发版扩展 ID：

```bash
./install_native_host.sh <当前扩展ID>
```

然后在 `chrome://extensions` 中重新加载扩展。

### Native Host 已退出

重新运行安装脚本，并检查：

```bash
ls -l "$HOME/Library/Application Support/Xiaoyuzhou Desktop Native Host"
cat "$HOME/Library/Application Support/Google/Chrome/NativeMessagingHosts/com.xiaoyuzhou.desktop.json"
```

清单中的 `allowed_origins` 必须与当前扩展 ID 一致。

### 绝对路径保存失败

- 确认 Native Host 已连接。
- 确认目标目录属于当前用户且具有写权限。
- 不要把文件路径填入目录字段。

### 本地 Qwen ASR 未安装

执行：

```bash
brew install ffmpeg uv
./install_local_asr.sh
```

安装后重新打开设置页，确认本地运行时状态。

### Qwen ASR 返回 404 或 403

- 优先填写 Base URL，让程序根据模型自动补全路径。
- 确认 API Key、地域和 Workspace Endpoint 匹配。
- 长音频使用 `qwen-audio-3.0-asr-flash-filetrans`。
- 修改 `native_host.py` 后重新运行 `install_native_host.sh`。

### AI 总结接口报 `chat/completions`

填写 Provider 的 Base URL 或官方完整 Endpoint，不要混用其他 Provider 的域名。
保存设置后，Native Host 会自动补全 `chat/completions` 路径。

## 14. 更新项目

拉取新代码后重新安装 Native Host，以同步 Python 文件和 Worker：

```bash
git pull
./install_native_host.sh <当前开发版扩展ID>
```

如果本地 ASR 依赖版本有变化，再执行：

```bash
./install_local_asr.sh
```

最后在 `chrome://extensions` 中重新加载扩展。

## 15. 卸载与清理

先从 Chrome 删除扩展，再执行：

```bash
rm -rf "$HOME/Library/Application Support/Xiaoyuzhou Desktop Native Host"
rm -f "$HOME/Library/Application Support/Google/Chrome/NativeMessagingHosts/com.xiaoyuzhou.desktop.json"
security delete-generic-password -s com.xiaoyuzhou.desktop -a asr.qwen 2>/dev/null || true
security delete-generic-password -s com.xiaoyuzhou.desktop -a asr.doubao 2>/dev/null || true
for account in summary.qwen summary.doubao summary.deepseek summary.kimi summary.glm; do
  security delete-generic-password -s com.xiaoyuzhou.desktop -a "$account" 2>/dev/null || true
done
```

Hugging Face 模型缓存不会被上述命令删除。如需释放磁盘空间，请在确认不再使用
后手动删除对应的 Qwen3-ASR 缓存目录。
